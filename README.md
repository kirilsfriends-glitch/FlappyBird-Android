# TRIGLYPH · ТРИГЛИФ · 三纹密码

**Каскадный шифр для китайского, русского и английского языков.**
Чистый Python, ноль внешних зависимостей, всё проверено официальными тест-векторами.

🇷🇺 Русский · [🇬🇧 English](README.en.md) · [🇨🇳 中文](README.zh.md) · [Спецификация формата](docs/SPEC.md) · [Модель угроз](docs/THREAT_MODEL.md)

```
                 открытый текст
                        │
   ①  XChaCha20-Poly1305 │  256-битный ключ, 192-битный нонс, тег 128 бит
                        ▼
   ②  AES-256-GCM        │  независимый 256-битный ключ, тег 128 бит
                        ▼
   ③  Threefish-1024-CTR │  независимый 1024-битный ключ, 80 раундов
                        ▼
   ④  HMAC-SHA3-512      │  подпись всего контейнера целиком
                        ▼
                    шифртекст
```

Чтобы прочитать сообщение, противнику нужно сломать **все три шифра сразу** —
ключи слоёв независимы и выводятся HKDF-SHA512 с доменным разделением.
Падение любого одного алгоритма (даже полное) не раскрывает открытый текст.

---

## Зачем это, если есть AES

Обычные библиотеки шифруют *байты*. Тексту на трёх языках этого мало — он
протекает там, где байтовый шифр даже не смотрит:

| Утечка | Что видит противник | Что делает TRIGLYPH |
|---|---|---|
| **Длина** | В UTF-8 иероглиф = 3 байта, кириллица = 2, латиница = 1. По длине шифртекста язык сообщения читается сразу | Набивка Padmé + «языковые корзины»: `黎明时分进攻`, `Атака на рассвете` и `Attack at dawn` дают **одинаковый** размер контейнера |
| **Нормализация** | «й» бывает одним кодом U+0439 и двумя U+0438+U+0306; китайские IME дают полноширинные формы. Один и тот же пароль → разные ключи | NFC для текста, NFKC для пароля — до начала криптографии |
| **Транспорт** | Base64 всегда выглядит как base64 | Броня иероглифами (12 бит/знак), кириллицей (5 бит/буква), латиницей — шифртекст выглядит как текст |
| **Сигнатура** | По магическим байтам контейнер находится grep-ом | Стелс-оболочка: контейнер статистически неотличим от случайного шума |
| **Подбор пароля** | Русский/китайский пароль без нормализации теряет энтропию | Трёхступенчатый KDF: SHA3-512 → scrypt (память) → PBKDF2-SHA512 (время) |

### Командная строка

```bash
# текст → броня подбирается под язык автоматически
$ python3 -m triglyph enc -m "Атака начнётся на рассвете" -p "тайна"
ксйдоувщкбдаваибадараараадаавааааааааидчъшвсцэыьвьщопбкяеэонмкапэрньсхяцмйзщсчучун…

$ python3 -m triglyph enc -m "黎明时分发起进攻" -p "密码"
㊁卅假勅坐劀企丐企一倀丐丁一一一丠剏孧坤埢坿修哚圯厀凹寥妎嫊争噉咬仭伙咓借嬫夀…

# расшифровать (броня определяется сама)
$ echo "$CIPHER" | python3 -m triglyph dec -i - -p "密码"
黎明时分发起进攻

# файлы любого размера — потоково, с постоянной памятью
$ python3 -m triglyph encf отчёт.pdf отчёт.tgl -p пароль --profile hard
$ python3 -m triglyph decf отчёт.tgl отчёт.pdf -p пароль

# асимметрично: шифруем по публичному ключу, подписываем своим секретным
$ python3 -m triglyph keygen -o alice
$ python3 -m triglyph enc -m "секрет" --to alice.pub --sign bob.key
$ python3 -m triglyph dec -i msg.tgl --identity alice.key --expect-sender bob.pub

# разрезать ключ на 5 частей, нужны любые 3
$ python3 -m triglyph split -k 3 -n 5 --secret "мой главный ключ" --armor hanzi

# посмотреть, что внутри контейнера, не зная пароля
$ python3 -m triglyph inspect -i отчёт.tgl --json
```

Интерфейс полностью переведён: `--lang ru` (по умолчанию), `--lang en`, `--lang zh`.

### Библиотека

```python
import triglyph

# простой путь: текст в текст
armored = triglyph.encrypt_text("Атака на рассвете 黎明时分进攻", password="тайна")
print(triglyph.decrypt_text(armored, password="тайна"))

# байты, все параметры под контролем
blob = triglyph.encrypt(
    data,
    password="тайна",
    suite="triple",        # triple | dual | solo
    profile="hard",        # fast | balanced | hard | paranoid
    aad=b"счёт №42",       # открытые, но защищённые от подмены данные
    stealth=True,          # спрятать сигнатуру формата
)
data = triglyph.decrypt(blob, password="тайна", aad=b"счёт №42")

# асимметричный режим
priv, pub = triglyph.generate_keypair()
box = triglyph.encrypt(b"для получателя", recipient=pub)
assert triglyph.decrypt(box, private_key=priv) == b"для получателя"

# потоково для больших файлов
with open("big.iso", "rb") as fi, open("big.tgl", "wb") as fo:
    triglyph.encrypt_stream(fi, fo, password="тайна", suite="dual")
```

## Что внутри

| Компонент | Реализация | Проверено |
|---|---|---|
| Поточный шифр | ChaCha20, HChaCha20, **XChaCha20** | RFC 8439 §2.3.2, §2.4.2; draft-irtf-cfrg-xchacha §2.2.1 |
| Аутентификатор | Poly1305 | RFC 8439 §2.5.2 |
| AEAD | ChaCha20-Poly1305, XChaCha20-Poly1305 | RFC 8439 §2.8.2 |
| Блочный шифр | AES-128/192/256 (S-box вычисляется из GF(2⁸), не «зашит») | FIPS-197 Приложение C.1–C.3 |
| Режим AEAD | AES-GCM (GHASH с таблицей 4-битных окон) | McGrew & Viega, тест-кейсы 13–14 |
| Третий слой | Threefish-1024-CTR, 80 раундов | обратимость, лавинный эффект, чувствительность к твику |
| Вывод ключей | HKDF-SHA512 | RFC 5869 TC1, TC3 |
| Парольный KDF | SHA3-512 → scrypt → PBKDF2-SHA512 | детерминированность, привязка к соли и «перцу» |
| Асимметрия | X25519 (лестница Монтгомери) | RFC 7748 §5.2, §6.1 |
| Разделение секрета | Шамир в GF(2⁸) | все сочетания K из N, отказ при K−1 |
| Обязательство к ключу | SHA3-256 по подключу | контейнер нельзя «открыть» вторым ключом |

Всё это — стандартная библиотека Python: `hashlib`, `hmac`, `secrets`,
`unicodedata`, `struct`. Ни одного `pip install`.

### Необязательное ускорение

Если в системе есть пакет `cryptography`, AES-GCM и ChaCha20-Poly1305 считаются
через OpenSSL (AES-NI) — в десятки раз быстрее. Ускоритель включается **только**
после побайтовой сверки со встроенной эталонной реализацией на случайных
векторах при импорте; любое расхождение — тихий откат на чистый Python.
Формат контейнера от бэкенда не зависит.

## Стойкость: что гарантируется

* **Конфиденциальность.** Каскад из независимо ключёванных XChaCha20, AES-256 и
  Threefish-1024. Композиция не слабее сильнейшего слоя: внешний слой —
  биекция, он не может ослабить внутренние.
* **Целостность и подлинность.** Три независимых уровня: Poly1305 (слой ①),
  GCM-тег (слой ②) и HMAC-SHA3-512 по всему контейнеру. Любая изменённая,
  переставленная, повторённая или обрезанная часть отвергается — тесты
  переворачивают каждый байт контейнера и проверяют, что расшифрование падает.
* **Обязательство к ключу.** В заголовке лежит SHA3-256 от отдельного подключа.
  Контейнер привязан ровно к одному ключу — защита от атак типа
  *partitioning oracle* и от «двусмысленных» шифртекстов.
* **Нонсы.** Выводятся из мастер-секрета и номера фрагмента через HKDF. Для
  каждого сообщения генерируется свежая 32-байтовая соль, поэтому повторное
  использование нонса невозможно даже при одном и том же пароле.
* **Стойкость к перебору пароля.** `balanced` = 64 МиБ памяти + 210 000 итераций
  PBKDF2; `paranoid` = 1 ГиБ + 1 200 000 итераций. Память-затратная ступень
  обесценивает GPU- и ASIC-фермы.
* **Метаданные.** Скрыта длина (и, как следствие, язык). Скрыт получатель
  (по умолчанию в заголовке нет его отпечатка). По желанию скрыта сама
  сигнатура формата.

### И что **не** гарантируется — честно

* Это **программная** реализация на Python. Она не константна по времени
  относительно кэша (таблицы AES), поэтому не годится для сценариев, где
  противник исполняет свой код на том же ядре (общий хостинг, браузерные
  side-channel атаки).
* Стелс-оболочка — **обфускация, а не шифр**: гамма выводится из открытого
  префикса. Она убирает поиск по сигнатуре, но не добавляет ни бита стойкости.
* Threefish-1024 проверен структурно (обратимость, лавина), а не официальным
  KAT из Skein. Он намеренно поставлен **внешним** слоем: даже ошибка в его
  константах не ослабила бы внутренние AES и ChaCha и не повлияла бы на
  целостность, которую держит HMAC-SHA3-512.
* Постквантовой стойкости по асимметрии нет: X25519 падает перед алгоритмом
  Шора. Симметричная часть (256-битные ключи) остаётся разумной и в
  постквантовом мире (алгоритм Гровера ≈ 128 бит).
* Ключи живут в памяти Python, где нет гарантий затирания. `KeySchedule.destroy()`
  делает что может, но своп и сборщик мусора вне нашей власти.

Подробно: [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md).

## Броня: шифртекст как текст

```python
from triglyph import armor
data = b"secret bytes"
armor.encode(data, "hanzi")     # ㊂哀嫣塺凔嵞屟冞…   12 бит на знак
armor.encode(data, "cyrillic")  # ыджмтпрщхчолб…      5 бит на букву
armor.encode(data, "latin")     # c2VjcmV0IGJ5dGVz    base64url
armor.encode(data, "grouped")   # MNQXE-3DFOJ-2GK3Q   для диктовки голосом
armor.decode(text)              # тип определяется автоматически
```

У каждой брони своя контрольная сумма: потерянный при копировании символ
обнаруживается сразу и отличается от настоящей подделки.

## Производительность

Замерено на 2 ядрах в контейнере, чистый Python, без ускорителя:

| Сюита | Слои | Шифрование | Расшифрование |
|---|---|---|---|
| `solo` | XChaCha20-Poly1305 + HMAC | 1.06 МБ/с | 1.10 МБ/с |
| `dual` | + AES-256-GCM | 0.47 МБ/с | 0.46 МБ/с |
| `triple` | + Threefish-1024 | 0.21 МБ/с | 0.20 МБ/с |

| Профиль KDF | Память | Время |
|---|---|---|
| `fast` | 8 МиБ | 39 мс |
| `balanced` | 64 МиБ | 365 мс |
| `hard` | 256 МиБ | 1.4 с |
| `paranoid` | 1 ГиБ | 7.5 с |

Для сообщений (основной сценарий) время целиком определяется профилем KDF, а не
шифром. Для файлов в гигабайты ставьте `--suite dual` или `solo` — либо
поставьте `cryptography`, и слои ① и ② уйдут в OpenSSL.

## Структура проекта

```
triglyph/
  chacha.py     ChaCha20 / HChaCha20 / XChaCha20 / Poly1305 / AEAD
  aes.py        AES-128/192/256, CTR, GCM (GHASH с таблицами)
  threefish.py  Threefish-1024 + режим CTR
  kdf.py        HKDF-SHA512, парольный KDF, ключевое расписание, обязательство
  x25519.py     X25519 (RFC 7748)
  cipher.py     формат контейнера, каскад, потоковый режим, интроспекция
  armor.py      брони hanzi / cyrillic / latin / grouped
  text.py       нормализация, определение языка, Padmé и «корзины»
  shamir.py     разделение секрета в GF(2⁸)
  stealth.py    оболочка без сигнатуры
  backend.py    выбор реализации AEAD и сверка ускорителя с эталоном
  selftest.py   32 проверки по официальным векторам
  cli.py        командная строка на трёх языках
  i18n.py       строки интерфейса ru / en / zh
tests/          116 тестов (unittest, без внешних зависимостей)
web/            демонстрационный сервер и трёхъязычный интерфейс
docs/           спецификация формата и модель угроз
```

## Эталонные векторы формата

`docs/test-vectors.json` — 60 готовых контейнеров с ключами и ожидаемым
открытым текстом. Они зафиксированы в репозитории: тест
`tests/test_vectors_file.py` падает, если изменение кода ломает совместимость
формата, а сторонняя реализация на другом языке может проверить себя тем же
файлом.

```bash
python3 tools/verify_vectors.py -v     # 64/64 эталонных векторов совпали
python3 tools/gen_vectors.py           # перегенерировать (только при смене версии формата)
```

## Тесты

```bash
python3 -m unittest discover -s tests -v    # 116 тестов
python3 -m triglyph selftest -v             # 32 проверки по векторам
python3 -m triglyph bench                   # скорость на вашей машине
```

Тесты проверяют не только «расшифровалось обратно», но и то, что сломаться
обязано: переворот каждого байта контейнера, обрезание, дописывание,
перестановка фрагментов, понижение сюиты в заголовке, чужой отправитель,
потерянный символ брони, K−1 частей секрета.
